    1

    Git kyun chahiye?

    Samajh15 min

    Kya aapne kabhi files aise save ki hain?

    website.html
website_final.html
website_final_v2.html
website_final_PAKKA.html
website_final_PAKKA_sahi_wala.html

    Thodi der baad yaad hi nahi rehta ki kaunsi file sahi hai, kal kya badla tha, aur purana wala version kaise wapas laayein. Git yahi problem solve karta hai.

    Dukaan ka khata: Jaise dukaandar har lena-dena date ke saath khate mein likhta hai, waise hi Git aapke project ka har badlav likh kar rakhta hai: kya badla, kab badla, kisne badla. Ek hi file rehti hai, par uski poori history Git ke paas hoti hai.

    Git aapko 4 cheezein deta hai

    • History: har save point ki list, kabhi bhi dekh sakte hain.
    • Undo: kuch toot gaya? Pichhle achhe version par wapas.
    • Backup: GitHub par copy, laptop kharab ho jaaye tab bhi code safe.
    • Teamwork: kai log ek saath ek project par kaam kar sakte hain.

    Git ka sabse bada fayda kya hai?

    Sahi! Git ek khata hai jo har badlav yaad rakhta hai, taaki aap kabhi bhi peeche ja sakein.

    Pehla repository

    Gehraai se20 min

    Repository (chhota naam: repo) matlab woh folder jiski history Git rakh raha hai. Har project = ek repo.

    Naya khata kholna: git init ek folder ko bolta hai, "aaj se tumhara hisaab-kitaab rakha jaayega." Folder ke andar ek chhupa hua .git folder ban jaata hai. Wahi khata hai. Use kabhi haath mat lagaiye.

cd ~/"Claude work/vaastu-website"

# khata kholein
git init

# dekhein Git kya soch raha hai

    git status laal rang mein files dikhayega: "Untracked files". Matlab Git ne files dekhi hain par abhi unka hisaab nahi rakh raha.

    Sabse kaam ki command

    git status ko apna dost bana lijiye. Jab bhi confuse ho, yahi chalaiye. Yeh batata hai abhi kya badla hai aur aage kya karna hai.

    Repository kya hai?

    Sahi! Repo = project folder + uska khata (.git).

    Branch: rough copy, fair copy

    Gehraai se30 min
    School wali yaad: Sawaal pehle rough copy mein karte the, sahi ho jaaye to fair copy mein utaarte the. Git mein fair copy ka naam hai main branch. Har naye kaam ke liye ek rough copy (nayi branch) banaiye.

    Fayda: rough copy mein kuch bhi toot jaaye, fair copy (aapki live website) safe rehti hai.

    Khud karke dekhiye 
    # nayi rough copy banao aur usme chale jao
git switch -c rashifal-update

# ...index.html mein badlav, phir add + commit...
git add .
git commit -m "Is hafte ka rashifal"

# fair copy par wapas aao aur rough copy ka kaam mila do
git switch main
git merge rashifal-update
    Yaad rakhein

    git branch batata hai aap abhi kaunsi copy mein ho (star wali). Galat branch par commit karna sabse aam galti hai.

    Website par naya "Testimonials" section try karna hai. Sahi tareeka?

    Sahi! Rough copy (branch) mein try karo, pasand aaye to merge karo.

    8

    Pull Request: copy check karwana

    Gehraai se25 min
    Teacher se copy check: Pull Request (PR) ek request hai: "meri rough copy dekh lijiye, theek lage to fair copy mein utaar dijiye." GitHub par dikhta hai kya badla, log comment kar sakte hain, aur ek button se merge hota hai.

    PR ka safar

    1. Branch par kaam karke git push -u origin rashifal-update
    2. GitHub par peela banner aata hai: Compare & pull request. Dabaiye.
    3. Title aur chhota description likhiye: kya badla aur kyun.
    4. Files changed tab mein har badlav dekhiye. Laal hata, hara juda.
    5. Sab theek ho to Merge pull request. Branch delete kar dijiye.

    Akele kaam karte hue bhi PR useful hai: merge se pehle ek baar saare badlav aaram se dekhne ka mauka milta hai. Claude Code aksar aapke liye PR banata hai, aur aap review karke merge karte ho.

    PR merge karne se pehle sabse zaroori kya hai?

    Sahi! Review hi PR ka asli kaam hai.

    Galti sudhaarna aur .gitignore

    Gehraai se30 min

    Galti sabse hoti hai. Git ka asli jaadu yahi hai ki galti theek ho jaati hai.

    HalatCommand
    File mein badlav kiya, pasand nahi aaya, commit nahi kiyagit restore index.html
    Galat file stage par chali gayigit restore --staged file
    Abhi-abhi kiye commit ka message galat hai (push nahi kiya)git commit --amend -m "Naya message"
    Purana commit galat tha, push bhi ho chukagit revert <commit-id>

    git revert sabse safe undo hai: yeh purana commit mitata nahi, uska ulta ek naya commit banata hai. Khate mein galat entry kaat-te nahi, uske neeche sudhaar ki entry likhte hain.

    Abhi in se door rahein

    git reset --hard aur git push --force. Yeh kaam mita sakte hain. Inki zaroorat pade to pehle kisi se poochhiye, ya Claude ko bataiye.

    .gitignore: jo GitHub par kabhi nahi jaana chahiye

    Project mein .gitignore naam ki file banaiye. Jo naam isme likhe, Git unhe ignore karega.

    # .gitignore
.env
.DS_Store
node_modules/
*.log

    Passwords, API keys aur client ka data kabhi commit mat kijiye. Public repo mein yeh poori duniya dekh sakti hai, aur delete karne ke baad bhi history mein reh jaata hai.

    Kal ka commit galat tha aur GitHub par push ho chuka hai. Kya karein?

    Sahi! Revert history ko surakshit rakhte hue galti ulta deta hai.
